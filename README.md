# espeak-ng-esp32

*[Português](README.pt-BR.md)*

**eSpeak NG as a native ESP-IDF component for the ESP32-S3, with Brazilian Portuguese speech — and a study of how
intelligible it is to real listeners.**

> **Status: Phase 3 (construction), not released.** The component builds, the reference board speaks, and its PCM is
> bit-identical to upstream eSpeak NG on the host for the verification corpus (100 of 100 items). Nothing here is a
> tagged release yet, and no intelligibility result exists: that needs the listening study. The test plan is in
> [`testing/test-plan.yaml`](testing/test-plan.yaml); the specification is in
> [`docs/Functionality/FSD.md`](docs/Functionality/FSD.md). Contributions are welcome — see
> [CONTRIBUTING.md](CONTRIBUTING.md).

## Why

- Several projects already run eSpeak NG on microcontrollers (Arduino libraries for ESP32/RP2040, one recent ESP-IDF
  port), but there is **no eSpeak NG component in the Espressif Component Registry** and no published, measured
  account of running it next to Wi-Fi, BLE and a display.
- There is **no published listening study of embedded text-to-speech in Brazilian Portuguese** — not with sighted
  listeners, not with blind or low-vision listeners, not for drug names. Automated checks are not intelligibility.

The survey behind these claims is in [`docs/Ideia/pesquisa-2026-11-26/`](docs/Ideia/pesquisa-2026-11-26/) (pt-BR).

## What it does

- eSpeak NG **1.52.0, sources unmodified**, built as an ESP-IDF component (`components/espeak-ng`), with the engine's
  `.bss` in PSRAM by default (about 341 KB of internal RAM stay free after boot).
- Voice and dictionary data in **their own flash partition**, with a checksummed header, read through a small
  read-only VFS. The languages in the image are chosen at build time and a capacity report is checked then.
- Asynchronous layer with cancellation; the synthesis task keeps its stack in PSRAM. `espk_synth()` needs a stack of at
  least 48 KB; use `espk_say()` otherwise.
- The Unicode `isw*` functions are redirected to `ucd-tools`, which is what makes accented Portuguese letters speak
  instead of being spelled out (upstream issue #1611); an intact mode without the redirection is available for study.
- The development bench is **silent by decision**: the driver refuses to play sound unless the responsible lifts it.

## Support by chip

| Chip | Level |
|---|---|
| ESP32-S3 | verified on the board |
| ESP32, ESP32-S2, ESP32-P4 | built in CI (`hello` example); not run on hardware |

Every chip needs PSRAM for the engine's data and stack.

The image with **every** language does not fit the reference board's 9.9 MB `espeak` partition, and the largest
dictionaries (Russian, for one) ask for about 9.2 MB of PSRAM at their peak. Pick the languages you need.

## Reference hardware

[Waveshare ESP32-S3-RLCD-4.2](https://www.waveshare.com/) — ESP32-S3, 16 MB flash, PSRAM, ES8311 codec, speaker,
reflective LCD.
